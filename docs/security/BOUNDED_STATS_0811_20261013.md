# Animus 0.8.11 — bounded statistics failure handling

## Trigger and resulting behavior

Root observed a real `sqlite3.OperationalError: interrupted` after the two-second
statistics deadline in the promoted 0.8.10 server. `/admin/api/stats` did not handle
that exception; its HTTP500 also disrupted the client's persistent HTTP session.
The cheap database health check still completed in approximately 5ms. This report
is the source remediation and its fixture evidence, not a claim of deployment.

Version 0.8.11 retains the authenticated transport/registry remediation and the
Windows durable updater source on this branch. It does not increase the daemon's
memory limit or the two-second statistics budget.

## Statistics contract

- Each refresh opens its own `mode=ro`, `query_only` SQLite connection. It never
  installs a progress handler on the writer's connection or waits on its lock.
  A read transaction pins one consistent snapshot across all aggregates.
- All five aggregate queries explicitly use existing covering indexes. Unique
  counts include the existing empty-workspace behavior. No memory content or
  provider configuration is read. Reader page cache is capped at 512KiB; this is
  not a claim of a total RSS bound or a host page-cache limit.
- Only one refresh can run per engine process. Fresh results have a 30-second TTL.
  An ingestion/deletion marks the old snapshot stale, retaining its counts;
  it does not trigger a full scan per write. After TTL, the next request may refresh.
- SQLite busy timeout is 250ms. Query progress retains the existing two-second
  budget, checked every 10,000 VM instructions. A failed refresh backs off 30seconds.
  A single oversized query can still exhaust that budget; this fix reports it
  truthfully instead of claiming an empty or healthy-fresh memory bank.
- `stats_status` is `fresh`, `stale`, or `unavailable`; `stats_degraded`,
  `stats_reason`, `stats_age_seconds`, `stats_collected_at`, and
  `stats_retry_after_seconds` expose the condition. Age/collection time refer to
  the start of the consistent read snapshot, not the failed refresh time.
- With a last known snapshot, timeout/busy/unavailable DB returns its actual
  counts and collection time, with stale/degraded status. With no valid snapshot,
  peer/admin APIs return structured 503 JSON plus `Retry-After: 30`; counts are null.
  Reasons are safe constant enums; SQL, exception text and private data are absent.
- Dashboard and other pages using index stats, CLI and MCP report status/age and
  tolerate null counts. The dashboard displays `Unavailable`, not a false zero.
  `/health` performs its actual cheap read of the required memories table every
  request and separately labels cached statistics. An old snapshot does not mask
  a failed database health read. Liveness never triggers counts.
- A new empty local CLI index retains lazy initialization for compatibility;
  existing wrong-schema databases are not migrated by the statistics reader.

The cache is process-local and does not survive restart. A cold timed-out scan is
an agent-owned operational pending item, even when liveness is healthy. Persisted
incremental statistics or a separately qualified asynchronous count worker may be
considered if real covering queries consistently exceed the budget; neither is
silently substituted in this patch.

## Evidence on the VPS

Existing native interpreter `/opt/animus-peer/bin/python`; private temporary
SQLite fixtures, no production DB/config/key mutation, no install/build/container
or external network. New tests use real SQLite rather than synthetic DB errors.

`tests/security/test_bounded_stats.py` qualifies interruption (actual SQLite VM
progress callback), cold failure/backoff, stale preservation/deep copy, actual
exclusive lock, active WAL writer plus index-writer lock, single flight, wrong
schema, covering EXPLAIN plans, consistent counts across a separate committed
writer, admin/peer 503 JSON, page status and independent cheap health.

Final local validation: **279 passed in 14.91s**, exit 0; the new bounded-statistics
module independently passed **10 tests in 0.87s**, exit 0. Exact command:

```sh
/opt/animus-peer/bin/python -m pytest -q tests/security tests/test_security_remediation.py tests/test_engine.py tests/test_server.py tests/test_active.py tests/test_mcp.py tests/test_cli.py tests/test_updater.py tests/test_crypto.py tests/test_config.py tests/test_helper_config.py tests/test_admin_auth.py tests/test_licensing.py tests/test_service.py tests/test_peer.py tests/test_sync.py
```

The HTTP tests use one ASGI TestClient without application lifespan. They prove
handled responses rather than an uncaught exception; they do not prove TCP
keepalive, Docker budget, a production-size cold query, or a Windows restart.
Windows native updater runtime/AST gates remain separately required.
